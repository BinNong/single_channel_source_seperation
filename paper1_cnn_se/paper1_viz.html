Single-Channel Blind Source Separation
for Co-Frequency Communication Signals

A complex-valued lightweight CNN with complex squeeze-and-excitation attention that separates two overlapping BPSK/QPSK/8PSK/16QAM signals arriving at the same antenna, same frequency, same time — using only 235K parameters on a single RTX 4060.

235K parameters 4 residual blocks 4096 complex samples / signal ~100 epochs to convergence 8 GB GPU memory

01The problem: two signals, one wire

Imagine two radios broadcasting simultaneously on nearly the same carrier (only a few Hz apart). The receiver captures one waveform — a sum of both signals plus noise. From that single channel we must recover each source.

Source 1 (QPSK @ 2000 Hz)
Time-domain real part · I/Q constellation · Spectrum (FFT magnitude)
Source 2 (BPSK @ 2005 Hz)
A different modulation and a carrier only 5 Hz away — classical filtering fails.
The mixture — what the receiver actually sees
y(t) = α·s₁(t) + (1−α)·s₂(t) + n(t),   α ~ U(0.4, 0.6),   SNR 0 dB here.
Why this is hard
With only 5 Hz between carriers (vs. ~2 kHz symbol rate), the two spectra almost completely overlap. Classical frequency-domain filters cannot tell them apart. The constellation looks like a featureless noise cloud. The model has to learn to undo co-channel interference end-to-end.

Why pulse-shape first, modulate later?
The RRC (Root-Raised Cosine) filter limits bandwidth before upconversion. Without it the spectrum would be a sinc with infinite extent — illegal in any real channel. The trade-off is roll-off (here 0.35): more bandwidth efficiency, more inter-symbol interference, which the receiver will need an equalizer for.

03Mixing: two sources collide

Once we have two well-formed signals, generating a training example is a one-liner: pick a random amplitude ratio α ∈ [0.4, 0.6], mix them linearly, and add AWGN at the chosen SNR.

y(t) = α · s₁(t)  +  (1 − α) · s₂(t)  +  n(t),    α ∈ [0.4, 0.6]
Mixing two signals
Note the headroom this gives us
Because α ≈ 0.5, a "do nothing" model that always outputs 0.5 · mixture for both sources gets a non-trivial baseline (~-6 dB SDR). The model's learnable output_scale is initialized exactly to 0.5 so the network starts at that "smart average" baseline — it must improve from there.

04Why complex tensors? The I/Q plane

Communication signals are bandpass — their information lives in a slow envelope around a fast carrier. We represent them as complex baseband: real part = I (in-phase), imag part = Q (quadrature).

Constellation diagrams — the "fingerprint" of each modulation
BPSK · 2 points
QPSK · 4 points
8PSK · 8 points
16-QAM · 16 points
Implication for the model
Every tensor in the model is torch.complex64 — channels and activations stay complex end-to-end. Casting to real-valued (concatenating I and Q as 2 real channels) loses phase information in every layer. The whole architecture — convolution, BN, ReLU, SE — needs its own complex-domain versions.

05Complex-valued 1D convolution

The cornerstone layer. The algebra is just multiplication of complex numbers, factorized into real-only ops so we can use stock nn.Conv1d internally:

(a + jb) · (u + jv) = (au − bv) + j(av + bu)

In PyTorch this becomes two real convolutions whose outputs are linearly combined:

# Input x = a + jb, weight w = u + jv (per channel, per kernel position) return torch.complex( self.real_conv(x.real) - self.imag_conv(x.imag), # a·u − b·v self.real_conv(x.imag) + self.imag_conv(x.real), # a·v + b·u )

The two real convolutions share the same filter bank conceptually — real_conv carries the u weights, imag_conv carries the v weights.

Why this matters mathematically
A complex convolution is a linear map on ℂ. If you instead cast to 2-channel real, the real network has 4× the parameters in the kernel and must learn the cross-coupling between I and Q in every layer. The complex form bakes that coupling into the algebra — strictly more sample-efficient.

06Complex Squeeze-and-Excitation — the core innovation

Inside every residual block, the SE module learns which channels to listen to. This is the part unique to Paper 1 — and the trickiest.

The block takes a complex feature tensor [B, C, T] and returns one of the same shape, scaled channel-wise:

1. Squeeze

Pool real & imag, concatenate

Global-average-pool each half of the complex channel separately, yielding [B, C] real and [B, C] imaginary descriptors. Concat → [B, 2C].
2. Excitation

FC → ReLU → FC → Sigmoid

Two fully-connected layers with a bottleneck of size 2C/r (here r=4). Sigmoid squashes each output to [0, 1] — a learned per-channel importance weight.
3. Scale

Apply real weight to complex feature

Average the two sigmoid outputs per channel: w = (sᵣ + sᵢ)/2 ∈ [0, 1]. Multiply complex feature by this real scalar — preserves phase, scales magnitude.

Why a real weight, not a complex one?

A complex feature r · e^{jθ} encodes (magnitude, phase). Multiplying by a real number w:

w · (r · e^{jθ}) = (w · r) · e^{jθ} — phase θ preserved, magnitude scaled.

This is the right inductive bias for a constellation-style problem: the set of "good" phases for source 1 are the QPSK grid; rescaling them by a common magnitude per channel doesn't shift the constellation — it just emphasises or dampens that channel's contribution to the final mask.

What does it learn, concretely?

The FC stack is tiny — 2C → C/4 → 2C with C=32 that's 64→8→64 = 1,040 parameters per SE block. With 4 residual blocks the model gains ~4K extra params but several dB of separation quality, because the gating learns to silence channels dominated by noise and emphasise channels carrying symbol structure.

Why this size matters
Real-valued baselines of equivalent quality need ~500K–1M parameters. The complex formulation packs 2× the information per parameter, and the SE gate economises on channel width without losing expressivity — 235K comfortably trains on an 8 GB GPU with batch 16.

09Why predict masks, not the sources directly?

The decoder outputs two complex tensors the same shape as the mixture. We don't output sources — we output masks. Each source is then mask × mixture, element-wise.

ŝ₁ = m₁ ⊙ y,    ŝ₂ = m₂ ⊙ y

The "ideal" masks are m₁ = s₁/y and m₂ = s₂/y — just the per-sample source/mixture division. The network is supervised to approximate these.

Why this works better than direct regression

  • Energy conservation is implicit. ŝ₁ + ŝ₂ ≈ y falls out automatically if the masks sum to ~1.
  • Trivial solution is sensible. Setting both masks to 0.5 gives ŝ₁ = ŝ₂ = 0.5·y — the best amplitude-balanced average of the two sources. The model's output_scale starts exactly there.
  • Permutation invariance. The model doesn't know which output is "source 1" vs "source 2" — the loss handles the assignment via the permutation-invariant trick below.

Permutation-invariant loss

Since the model can swap its two outputs without semantic penalty, the loss must try both orderings:

loss = min{   L(ŝ₁, s₁) + L(ŝ₂, s₂),    L(ŝ₁, s₂) + L(ŝ₂, s₁)  }

10Training dynamics

Adam, learning rate 1e-3, 100 epochs, batch 16. The loss is complex MSE by default, but the same code supports SI-SDR and a combined loss. Gradient clipping at norm 1 keeps the early epochs stable.

Generalisation to unseen frequencies
Trained at fixed 5 Hz gap, the model still degrades gracefully at 2–10 Hz gaps (its training neighbourhood). Paper 2 closes that gap with a state-space backbone.
